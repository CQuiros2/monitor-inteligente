Los monitores tradicionales usan umbrales fijos. No aprenden el comportamiento del sistema ni detectan patrones complejos de anomalías.

Código del Agente — Go
// Lee métricas y las envía al servidor
func collectAndSend(conn net.Conn) {
  for {
    m := Metrics{
      CPU: readCPU(), // /proc/stat
      Memory: readMemory(), // /proc/meminfo
      Net: readNetwork(),// /proc/net/dev
      Procs: countProcs(), // /proc/[pid]
      Time: time.Now().Unix(),
    }
    data, _ := json.Marshal(m)
    fmt.Fprintf(conn,"%s\n",data)
    time.Sleep(5*time.Second)
  }
}
  • Lee /proc/stat para calcular % CPU usado vs idle
  • Lee /proc/meminfo para RAM disponible vs total
  • Lee /proc/net/dev para bytes recibidos por interfaz
  • Serializa a JSON y envía por TCP cada 5 segundos
  • Reconexión automática si el servidor no responde
  • Overhead: <0.5% CPU · <15MB RAM

Isolation Forest — ¿Cómo funciona?
  • No supervisado: no necesita datos etiquetados de anomalías previas
  • Isolation Trees: construye 100 árboles aleatorios de decisión
  • Principio: una anomalía se aísla con POCAS particiones del espacio
  • Umbral dinámico: detecta cuando CPU supera 2x el promedio histórico
  • Severidad: HIGH si CPU >90% · MED si CPU >85%
  • Botón de demo: inyecta métricas de CPU 88-98% en tiempo real
// INPUT — 4 features
CPU (%) · Memoria (%) · Red (KB) · Procesos (#)
// OUTPUT
+1 → Normal    −1 → Anomalía HIGH/MED
+ anomaly score continuo
// REFERENCIA
Liu, Ting y Zhou (2008) IEEE ICDM
Yahoo Research: >90% precisión (Laptev et al., 2015)
